# deedlog（ディードログ）

**行われたことを、書き換えられない記録に。**

deedlog は、システムが何をしたかを追記専用のチェーンに記録し、独立した連署サーバーと信頼できるタイムスタンプで固定し、
運営者を信頼しなくても誰でも検証できるようにする OSS です。

[English](README.md) · ステータス：開発初期。v1.0 までは互換性のない変更があり得ます。

## なぜ必要か

サイバー攻撃は速く、安くなっています。最近の情報漏洩の多くで流出したのは、本来そこに残っている必要のなかったデータです。
何年も前の問い合わせフォームの入力が外部サービスに残っていた、書き出したファイルが共有フォルダに置かれたままだった、といった具合です。

対策はデータの階層化（ティアリング）です。不要になったものは削除し、保管が必要なものは安全な場所に移す。
そして、たいてい欠けている最後の一歩が、「実際にそうしている」ことを第三者が確かめられる形で示すことです。
いまその証拠は組織自身が持っていて、書き換えも、記録から外すことも、相手ごとに違う内容を見せることもできます。

deedlog は削除や移動をその場で記録し、どの当事者もこっそり変えられず、誰でも後から確かめられるチェーンにします。
予定を宣言しておけば、行われるはずだった削除が行われていないことも、記録の空白として見えます。

AI エージェントやローコードの自動化が決められたことだけをしたことなど、システムが何をしたかを他者に信じてもらう場面にも、同じ仕組みが使えます。

## 仕組み

```
記録 ──▶ チェーン ──▶ チェックポイント ──▶ 検証
         ハッシュで    署名・連署サーバーの連署・ 誰でも、オフラインで、
         つなぐ        タイムスタンプ            ブラウザでも
```

- **チェーン**：各記録が直前の記録のハッシュを持つ。記録に入るのは証拠のハッシュだけで、証拠そのものは入らない。
- **チェックポイント**：運営者がチェーンのマークル木の根に署名し、独立した連署サーバー（英語では witness）が連署（C2SP 形式）、
  RFC 3161 のタイムスタンプ局が時刻を証明する。矛盾する 2 つのチェックポイントはそのまま不正の証明になる。
- **受領証**：出来事に関わった人に「どこに記録したか」の署名付きの約束を渡す。記録から外すと証明できる。
- **ブロックチェーンではない**：合意形成もトークンもない。[信頼モデル](spec/trust-model.md)を参照。

## はじめかた

```sh
git clone https://github.com/deedlog/deedlog && cd deedlog
go install ./cmd/dlog

dlog verify docs/sample/chain.jsonl
dlog keygen -name example.com/log -out operator
dlog checkpoint -key operator.key docs/sample/chain.jsonl > checkpoint
dlog verify -checkpoint checkpoint -key operator.vkey docs/sample/chain.jsonl
```
