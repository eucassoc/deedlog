# deedlog for JavaScript

The JavaScript implementation of [deedlog](https://github.com/eucassoc/deedlog):
chains of records linked by hash, checkpoints and witness cosignatures in the
C2SP formats, and anchoring. One file, no dependencies. It runs unchanged in
Cloudflare Workers, in Node 20 or later and in browsers; the only thing it
asks of the platform is Web Crypto with Ed25519.

The Go implementation (`core/` and the `dlog` tool) and this one are held to
the same [conformance vectors](../testdata/conformance): the same input gives
the same bytes in both, and each accepts what the other writes.
[docs/implementations.md](../docs/implementations.md) lists what each has.

Status: early development; expect breaking changes until v1.0.

## Install

```sh
npm install deedlog
```

```js
import * as deedlog from 'deedlog';
```

## Use

Record what happened, and check a chain:

```js
const lines = [];
const { line, body } = deedlog.makeRecord(deedlog.readChain(lines), {
  name: 'example.com/log',
  source: { type: 'form', id: 'contact', collector: 'my-service 1.0' },
  event: 'data.deleted',
  meta: { item: '3f2a', by: 'support' },
});
lines.push(line); // store the line as it is: digests are of its bytes

const chain = deedlog.readChain(lines);
if (chain.problems.length) throw new Error(`line ${chain.problems[0].line}: ${chain.problems[0].reason}`);
```

Sign a checkpoint and have a witness cosign it:

```js
const signer = await deedlog.parseSigner(OPERATOR_KEY); // from `dlog keygen`, or generateKey()
const leaves = lines.map((l) => deedlog.leafHash(l));
let note = await deedlog.signCheckpoint(leaves, signer);
const witness = deedlog.parseVerifier(WITNESS_VKEY);
const post = async (body) => {
  const r = await fetch(`${WITNESS_URL}/add-checkpoint`, { method: 'POST', body });
  return { status: r.status, body: await r.text() };
};
note += (await deedlog.requestCosignature(note, leaves, witness, post)).lines.join('');

const checkpoint = await deedlog.verifyCheckpoint(note, deedlog.parseVerifier(OPERATOR_VKEY), [witness], 1);
```

`addCheckpoint` is the witness's side of the same call; `anchor`,
`recordProof` and `commitOf` are anchoring
([spec/anchoring.md](../spec/anchoring.md)). Every exported function has a
comment in [`deedlog.js`](deedlog.js) saying what it does.

## In a browser, without a build step

The file is a plain ES module with no imports, so a page can load a copy of
it. Copy it from the installed package with a script, commit the copy, and
never edit it:

```js
// scripts/vendor.mjs — run after updating the dependency
import { readFileSync, writeFileSync } from 'node:fs';
const { version } = JSON.parse(readFileSync(new URL('../node_modules/deedlog/package.json', import.meta.url), 'utf8'));
const source = readFileSync(new URL('../node_modules/deedlog/deedlog.js', import.meta.url), 'utf8');
writeFileSync(new URL('../public/vendor/deedlog.js', import.meta.url),
  `// GENERATED by scripts/vendor.mjs from deedlog ${version} (Apache-2.0, github.com/eucassoc/deedlog).\n// Do not edit: update the dependency, then run the script again.\n${source}`);
```

Code that runs on the server imports `deedlog`; the page imports
`./vendor/deedlog.js`. A test that compares the two keeps the copy from
drifting.

## Why one file

The same code has to run in a witness, in an operator's service and in the
browser of someone checking a record, and the last of these should be able
to read what it runs. So there is no build, there are no dependencies, and
SHA-256 is implemented here: a Merkle root is many small hashes, and Web
Crypto's digest is asynchronous. Ed25519 is the platform's.

What is not here, and why, is in
[docs/implementations.md](../docs/implementations.md): RFC 3161 timestamps,
receipts and proofs of misbehavior are in the Go implementation only.
